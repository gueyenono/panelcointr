# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`panelcointr` is an R package (R >= 4.6 available locally via nix) implementing panel cointegration tests robust to cross-section dependence and structural breaks. The numerics are in Rust (extendr). Implemented: `pcoint_westerlund()` (Westerlund 2007; design and decisions in `plan/westerlund.md`).

## Commands

Run from the repo root:

```sh
Rscript -e 'devtools::document()'                 # compile Rust, regenerate R/extendr-wrappers.R, NAMESPACE and man/
Rscript -e 'devtools::test()'                     # run all tests
Rscript -e 'devtools::test(filter = "panel")'     # run one file: tests/testthat/test-panel.R
Rscript -e 'devtools::check()'                    # full R CMD check (currently 0 errors/warnings/notes)
Rscript -e 'devtools::load_all()'                 # load package for interactive use (debug build of the Rust code)
(cd src/rust && cargo test --offline)             # Rust unit tests of src/rust/src/core
```

### Rust

- Crate in `src/rust`: `src/lib.rs` holds the extendr wrappers only; the numerics are in `src/core/` (no extendr types, tested with `cargo test`). `R/extendr-wrappers.R` is generated by the `document` binary during the build; never edit it.
- MSRV is 1.71 (`rust-version` in `Cargo.toml`, `SystemRequirements` in DESCRIPTION). It covers the whole dependency tree, so after changing dependencies re-resolve with `CARGO_RESOLVER_INCOMPATIBLE_RUST_VERSIONS=fallback cargo update` (cargo >= 1.84), check `Cargo.lock` still says `version = 3`, then re-vendor.
- Re-vendor after any change to `Cargo.lock`: `Rscript -e 'rextendr::vendor_crates(clean = TRUE)'` (writes `src/rust/vendor.tar.xz` and `vendor-config.toml`), then `Rscript -e 'rextendr::write_license_note()'` and restore the extendr authors ("The extendr developers") that cargo metadata leaves empty in `LICENSE.note`.
- Set `CARGO_HOME` to a scratch directory when running cargo by hand, so nothing is written to `~/.cargo`.
- Benchmarks (`inst/bench/`) need a release build: install with `R CMD INSTALL .` rather than `load_all()`.

## Conventions

- Roxygen2 with markdown enabled; `NAMESPACE` and `man/` are generated, so edit roxygen comments in `R/` and rerun `devtools::document()` rather than editing them directly.
- testthat 3rd edition; test files are `tests/testthat/test-<name>.R`, mirroring `R/<name>.R`.
- Add dependencies with `usethis::use_package()` so DESCRIPTION stays consistent (install them first; see Environment).
- Non-package directories (`literature/`, `plan/`, `data-raw/`, `CLAUDE.md`, `.claude/`) are listed in `.Rbuildignore`; add any new non-package top-level paths there too, or `R CMD check` will note them.
- `tests/testthat/helper-reference.R` is a pure-R oracle of the Westerlund engine; new settings must be added to it and to the T2 comparisons in `test-westerlund.R`.
- Keep R code, roxygen text and Rust error messages ASCII (use `\eqn{}` for math in roxygen).

## Environment

R, every R package and the Rust toolchain (cargo/rustc from fenix stable) come from nix through the user's home-manager flake at `~/home-manager/`. Install anything missing there, never with `install.packages()`, `pak`, `remotes` or `rustup`:

1. Check the package is in the pinned nixpkgs: `nix eval --raw --inputs-from ~/home-manager nixpkgs#rPackages.<name>.version`.
2. Add it to the `r_packages` list in `~/home-manager/modules/R/R-packages-list.nix`. Packages missing from nixpkgs need a derivation in that file (see the `*_gh` entries).
3. Run `hms` (`home-manager switch`), then confirm with `Rscript -e 'library(<name>)'`.

`~/home-manager/CLAUDE.md` documents that repo. Leave committing there to the user.

## Reference literature

`literature/` holds the papers that specify the methods. Treat them as the specification: test statistics, critical values and asymptotic moments should be checked against them.

- `Westerlund-PanelCointegrationTests-2008.pdf`: Westerlund (2008, *JAE*), "Panel Cointegration Tests of the Fisher Effect" (Durbin–Hausman tests with cross-section dependence).
- `guid-984886be-…-ASSET1.0.pdf`: Westerlund (2006), "Testing for error correction in panel data", METEOR RM 056 (ECM-based tests Gt, Ga, Pt, Pa).
- `BANERJEE-COINTEGRATIONPANELDATA-2015.pdf`: Banerjee & Carrion-i-Silvestre (2015, *JAE*), "Cointegration in panel data with structural breaks and cross-section dependence".
- `bbs-dp2017-02.pdf`: Banerjee & Carrion-i-Silvestre (2017), "Testing for panel cointegration using common correlated effects estimators", Birmingham Business School DP 2017-02.

Read them with `pdftotext`, e.g. `pdftotext -f 5 -l 10 literature/<file>.pdf -`. Several PDFs start with a JSTOR or repository cover page, so PDF page numbers are offset from the papers' own.

`plan/` is for planning documents.
